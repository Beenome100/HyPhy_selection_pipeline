# Beenome selection analysis pipeline

This pipeline includes the [HyPhy](https://www.hyphy.org/) programs BUSTED and aBSREL.

Note: Run the pipeline on Atlas. The pipeline encounters errors on Ceres.

## 1. Load the conda environment

If you can access the Beenome shared conda environment directory:
```
conda activate /project/beenome100_collab/conda_envs/hyphy
```

Otherwise, create the conda environment from the environment YAML file. The environment name is "hyphy_pipemake_env".
```
conda env create --file hyphy_pipemake_env.yml
conda activate hyphy_pipemake_env
```

## 2. Run pipemake
```
pipemake msf-codon-selection \
    --msf-wildcard /path/to/orthogroup/sequence/files/{samples}.cds.fna \   
    --workflow-dir <output_folder_name> \
    --scale-threads 6 \
    --scale-mem 6
```
For `--msf-wildcard` change the path and sequence file extension to match your files.


## 3. Update the slurm script
Pipemake will print some text, including:
```
please use the following command within the test directory:
snakemake --use-singularity --singularity-args '--bind /path/to/orthogroup/sequence/files'
```

Update `'--bind /path/to/orthogroup/sequence/files'` in the slurm script.
<details>
<summary>slurm script</summary>

```
#!/bin/bash
#SBATCH --job-name=hyphy
#SBATCH --partition=atlas
#SBATCH --time=14-00:00:00
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=2
#SBATCH --mem=4G
#SBATCH --account=<your account>

module load apptainer
module load miniconda3
source activate
conda activate hyphy_pipemake_env

snakemake --executor slurm --jobs 100 \
    --latency-wait 60 \
    --default-resources \
         slurm_account=<your account> \
         slurm_partition=atlas \
         runtime="14d" \
    --use-singularity \
    --singularity-args '--bind /path/to/orthogroup/sequence/files' \
    --keep-going  
```
</details>


## 4. Update the Snakefile
Add the following line to the Snakefile generated by pipemake. The line goes right before the include text.
```
ruleorder: link_trim_msa_clipkit > link_reconstruct_tree_iqtree > trim_msa_clipkit > reconstruct_tree_iqtree
```


<details>
<summary>updated Snakefile</summary>

```
configfile: 'config.yml'

rule all:
    input:
        expand("Selection/absrel/{sample}.json", sample=config["samples"]),
        expand("MSA/Trimmed/{sample}.fa", sample=config["samples"]),
        expand("MSA/AA/{sample}.fa", sample=config["samples"]),
        expand("MSA/Codon/{sample}.fa", sample=config["samples"]),
        expand("Selection/BUSTED/{sample}.json", sample=config["samples"]),
        expand("iqtree/{sample}.fa.contree", sample=config["samples"]),

ruleorder: link_trim_msa_clipkit > link_reconstruct_tree_iqtree > trim_msa_clipkit > reconstruct_tree_iqtree

include: "pipemake/modules/msa_selection_absrel.smk"
include: "pipemake/modules/msa_trim_clipkit.smk"
include: "pipemake/modules/msf_align_codons_macse.smk"
include: "pipemake/modules/msa_selection_BUSTED.smk"
include: "pipemake/modules/msa_tree_iqtree.smk"
include: "pipemake/modules/msf_phylogeny_codon_links.smk"

```
</details>

<br>
This addresses a bug where two rules generate output files with the same name. 

## 5. Submit job
The `hyphy_pipemake_env` conda environment includes Snakemake with the SLURM executor plugin.

## 6. Restarting a killed job
When restarting a killed pipeline job (1) Execute `snakemake --unlock` first so that the resubmitted job can write to the same directory as before. (2) Add `--rerun-incomplete` to the Snakemake command.

<details>
<summary>restart script</summary>

```
snakemake --unlock

snakemake --executor slurm --jobs 100 \
    --latency-wait 60 \
    --default-resources \
         slurm_account=<your account> \
         slurm_partition=atlas \
         runtime="14d" \
    --use-singularity \
    --singularity-args '--bind /path/to/orthogroup/sequence/files' \
    --keep-going \
    --rerun-incomplete
```
</details>
